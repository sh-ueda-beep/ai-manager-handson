## Context

AI Managerは現在、PPTXファイルをアップロード→解析→レビューする一方向フローを提供している。レビューはBedrock AgentCoreのSSEストリーミングで実行され、結果はReviewPanelに構造化表示される。ユーザーがレビュー結果に対して追加の質問や深掘りを行う手段がなく、対話的なフィードバックが得られない。

既存のストリーミング処理（App.tsx `handleReview`）はfetch + ReadableStreamで実装されており、同じパターンをチャットにも適用できる。

## Goals / Non-Goals

**Goals:**

- レビュー完了後にチャットUIを提供し、レビュー内容についてAIと対話できるようにする
- Bedrock AgentCoreのセッションIDを維持し、レビューコンテキストを保持した会話を実現する
- メッセージのストリーミング表示で、応答をリアルタイムに表示する

**Non-Goals:**

- チャット履歴の永続化（DB保存）は行わない。セッション中のみ保持
- ファイル添付や画像送信などのリッチ入力
- 複数セッションの管理・切り替え
- レビュー実行前のチャット利用（レビュー完了が前提）

## Decisions

### 1. チャットUIの配置: ReviewPanel内にタブ切り替えで追加

**選択**: ReviewPanelの下部にチャット入力欄を配置し、レビュー結果とチャットを同一画面で表示する

**代替案**:
- 別パネルとして右側に追加 → 画面が3カラムになり狭くなる
- モーダル/ドロワーで表示 → レビュー結果を参照しながら質問しづらい

**理由**: レビュー結果を見ながら質問できる導線が最も自然。既存のレイアウト構造（2カラム）を維持できる。

### 2. セッション管理: レビュー時のセッションIDを再利用

**選択**: `handleReview`で生成する`crypto.randomUUID()`のセッションIDをstateに保持し、チャットでも同じセッションIDを使用する

**代替案**:
- チャット開始時に新規セッション → レビューコンテキストが失われる

**理由**: AgentCoreは同一セッションID内で会話履歴を保持するため、レビュー時のセッションIDを再利用すればレビュー内容を踏まえた応答が得られる。

### 3. ストリーミング処理: 既存パターンを共通hook化

**選択**: 既存の`handleReview`のSSEストリーミング処理をカスタムhook (`useAgentStream`) として切り出し、レビューとチャットの両方で再利用する

**代替案**:
- チャット用に別途ストリーミング処理を実装 → コード重複

**理由**: レビューもチャットも同じBedrock AgentCoreエンドポイント・同じSSE形式を使用するため、共通化が自然。

### 4. チャットメッセージの型: シンプルなメッセージ配列

**選択**: `{ role: 'user' | 'assistant', content: string }[]` のシンプルな配列でstate管理

**理由**: 永続化不要・セッション内のみの保持なので、最小限のデータ構造で十分。

## Risks / Trade-offs

- **セッションタイムアウト** → AgentCoreのセッションが切れた場合、エラーメッセージを表示してユーザーに再レビューを促す
- **長い会話でのコンテキスト超過** → AgentCore側のコンテキストウィンドウ制限に依存。MVP段階では制限なし、必要に応じてメッセージ数の上限を設定
- **ストリーミング中の入力制御** → AI応答のストリーミング中はテキスト入力・送信ボタンを無効化して二重送信を防ぐ
